Use

clawswap up, the session it opens, and the other commands.

Run every command from inside your project's repo, not clawswap's clone. bin/clawswap runs mix clawswap in clawswap's own folder, with your repo passed along.

Commands

CommandWhat it does
clawswap help [command]Lists the commands, or shows one command's usage and options. clawswap <command> --help (or -h) does the same.
clawswap doctorChecks what clawswap needs is installed (Elixir, zellij or tmux, Node.js, inotify-tools, a GitHub token, Chrome and chromedriver) and that the repo has a config and webhook, and prints the fix for what's missing. Exits 1 if something it needs is.
clawswap initWrites a starter clawswap.exs at the repo root (refuses if a config is already there).
clawswap upStarts the daemon if it isn't running, adds the project to it, and opens the zellij or tmux session, or re-attaches to it.
clawswap up <name|file>...The same, with override configs (clawswap.<name>.yml, say) merged over the config.
clawswap statusThe list the keys show, the current branch, the webhook's state and the last switch.
clawswap switch <branch>What a key press does. Follow it in the clawswap pane. The branch can be its full name, its PR number (switch 23), its short name or any part of its name that only one listed branch has.
clawswap pullPulls the current branch the same way. Does nothing if it's up to date.
clawswap updateRuns the steps for what changed since they last ran (after a git pull by hand, say).
clawswap update <rev>The steps for what changed since rev.
clawswap update --allEvery step.
clawswap walk [name...]Plays walkthroughs in Chrome: the ones named, else the ones this branch added or changed. --headless runs them without a window and exits 1 if one fails.
clawswap test [path...]Runs the project's browser tests (Wallaby) against the session's servers. --watch shows the windows, --only tag picks by tag.
clawswap browserOpens a dev Chrome at your app, that walkthroughs then play in.
clawswap smee [url]Adds the repo's GitHub webhook for the daemon's shared smee.io channel (up does this by itself; this tries again, or prints the steps to do it by hand), and points a running watcher at it. With a URL, or --new, the checkout gets a channel of its own (see Install).
clawswap layoutPrints the layout up opens: zellij's layout file, to start your own from, or the tmux commands that build the session.
clawswap completion installSets up Tab completion for your shell; clawswap completion <shell> prints the script for bash, zsh or fish (see Completion).
clawswap watchRuns the project in the daemon (starting the daemon if it isn't running) and shows its log. The session runs it in its clawswap pane; you rarely run it yourself.
clawswap reloadAfter changing or pulling clawswap: quits OpenDeck, copies the plugin into its plugins folder, starts OpenDeck again, then recompiles clawswap (clearing Hologram's page bundle) and restarts the daemon, and writes any installed completion again. It compiles before stopping the daemon, so a compile error leaves everything running. See Stream Deck keys for finding OpenDeck.
clawswap daemonThe daemon itself, which runs every project's watcher, page and API. up starts it in the background; you rarely run it yourself.

status, switch and pull talk to the project in the daemon, so they need clawswap up first.

A mistyped command says which command it thinks you meant (clawswap swich: "Did you mean clawswap switch?"), and a command given the wrong arguments says what it takes. Options work the same way for every command: they can go before or after the arguments, and one a command doesn't take stops it before it does anything, with the closest it does take (clawswap walk --headles: "Did you mean --headless?").

Completion

Tab completes clawswap's commands (clawswap re, Tab, gives clawswap reload), and for switch the branches on origin of the repo you're in (read with git, so pressing Tab doesn't start mix), and for up the override configs in the folder you're in. Set it up once:

clawswap completion install        # for the shell $SHELL names; or: clawswap completion install zsh

That saves the script where the shell looks for it, and says if the shell needs one more line first:

  • bash: ~/.local/share/bash-completion/completions/clawswap, which bash reads through the bash-completion package. Without it, add source ~/.local/share/bash-completion/completions/clawswap to ~/.bashrc.
  • zsh: ~/.zfunc/_clawswap. Put fpath=(~/.zfunc $fpath) in ~/.zshrc before compinit (or before oh-my-zsh is sourced).
  • fish: ~/.config/fish/completions/clawswap.fish, which fish reads by itself.

Then open a new terminal. The script is a copy of the command list, so clawswap reload writes the installed ones again once it has compiled (clawswap completion refresh does just that), and a command added since completes too. clawswap completion bash (or zsh, fish) prints the script, to save somewhere else.

clawswap up

up first makes sure the daemon is running on the config's port (starting it in the background if nothing answers there) and adds the project to it, so its page is up while the session starts (Several projects). Then, when no session is running, it:

  1. Runs the config's prepare steps (starting containers, say), waiting for any wait_for_port.
  2. Runs the steps for whatever changed since they last ran, all of them the first time, so the servers don't start on stale deps. It remembers the commit in .git/clawswap.json. If a step fails it says so and starts the servers anyway; fix it and run clawswap update.
  3. Starts the session: zellij with the generated layout (or the config's own layout), or tmux with the same panes.

clawswap up staging does the same with clawswap.staging.yml (or .exs) merged over the config: see Override configs.

When the session is already running, up attaches to it (from inside tmux, it switches to it). A session zellij lists as exited is deleted and started fresh, rather than coming back with its panes waiting for Enter.

zellij or tmux

clawswap runs the session in either. To choose, set multiplexer: :tmux (or :zellij) in clawswap.exs, multiplexer: tmux in clawswap.yml, or CLAWSWAP_MULTIPLEXER=tmux for one run. Without any of those it picks, in order:

  1. the one you run it inside, so clawswap up from a tmux window opens the session in tmux and switches to it;
  2. zellij, for a config with its own layout (a zellij layout file);
  3. zellij, if it's installed and 0.44 or newer;
  4. tmux, if it's installed and 3.1 or newer.

In tmux the panes are laid out as in zellij, with each one's name on its border. A switch restarts a server's pane with respawn-pane, so it keeps its place and size.

The session

The default layout stacks the servers on the left and puts the watcher and your other panes on the right:

  • a pane for each server, named as in servers;
  • one called clawswap, which runs clawswap watch: it keeps the project in the daemon and shows the project's log, where switch output shows;
  • one for each of the config's other panes; a pane with no command is an empty shell, at the repo root unless it has a cwd (shell: []).

Ctrl+Q leaves zellij (in tmux, Ctrl+B then D); clawswap up again comes back.

Each pane with a command runs it through bin/keep. When the command stops (Ctrl+C, or Ctrl+C twice for the watcher and other BEAM programs), the pane keeps a shell instead of closing, and the up arrow brings the command back. Without it, zellij closes a pane whose command has exited when you press Ctrl+C there, and tmux closes it as soon as the command exits.

Your own layout (zellij)

Start from clawswap layout > my-layout.kdl, edit it, and set layout: "my-layout.kdl" in the config. Keep the server panes named as in servers (the watcher finds them by name), and run clawswap watch in one pane: it runs the project in the daemon, and shows its log.

Several projects at once

Run clawswap up in each project. They share one daemon on 127.0.0.1:27390: the first up starts it in the background (its output goes to ~/.local/state/clawswap/daemon-27390.log), and each project comes into it with a watcher of its own.

  • Its page is http://127.0.0.1:27390/p/<id>, its id being its session's name (the config's name, else the folder's), in lower case. Two checkouts of one repo (worktrees) need a session each. http://127.0.0.1:27390 lists every project, with the branch it's on and how its last switch went.
  • Its log is in its session's clawswap pane, as before: the pane's clawswap watch follows it from the daemon.
  • Its environment. A project's steps run with the environment of the shell you ran clawswap up in (its PATH, its direnv), not the daemon's or another project's.
  • The selected project is the one the Stream Deck keys follow, unless they're pinned to a project (Stream Deck), and the one the API's paths without /p/<id> answer for. It's the first project to start, until you press Select on the front page, use or look at a project's page (its browser tab coming into view selects it), or press the deck's project key.
  • A config change (a switch that changes it, or a save on the settings page) starts that one project again on the new config; the others carry on.
  • When a session ends, its project leaves the daemon about 30 seconds later. The daemon stops by itself an hour after its last project has gone. If the daemon stops while a session runs, the session's clawswap pane starts it again and carries on.

A project with a port of its own gets a daemon of its own on that port, apart from the others: give it one when you'd rather it didn't share.

What clawswap keeps per checkout

.git/clawswap.json holds the commit the steps last ran for, and a smee.io channel of the checkout's own if you gave it one. It lives inside .git, so it's never committed and needs no .gitignore entry; worktrees get their own. The generated layout sits next to it as .git/clawswap.kdl (zellij only).
