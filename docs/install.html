Install

What clawswap needs, getting it, and putting the clawswap command on your PATH.

Requirements

WhatVersionWhy
Elixir1.19 or newerHologram, the page's framework, needs it.
Erlang/OTP26 or newerThe daemon is an OTP app. .tool-versions pins OTP 28, which mise install or asdf install gets you (its own Elixir).
zellij0.44 or newerIt added --pane-id to its CLI, which switches use. Ubuntu's package may be older; take the binary from the releases or cargo install --locked zellij.
or tmux3.1 or newerInstead of zellij. Distro packages are new enough (sudo apt install tmux). See zellij or tmux.
Node.jsany currentOnly at compile time: Hologram bundles the page's JavaScript with esbuild, which it installs with npm the first time. Nothing of clawswap's own is JavaScript.
inotify-toolsLinux onlyHologram's dev server watches its files with it: sudo apt install inotify-tools.
gh or GITHUB_TOKENoptionalFor pull-request titles, and to list only branches with an open PR.

Once it's cloned, clawswap doctor checks all of these (and Chrome and chromedriver for walkthroughs, and your project's config, origin and webhook when you run it in your repo) and prints the fix for anything missing. It runs with plain elixir, so it works before mix compile does.

Get clawswap

git clone https://github.com/cbishopvelti/clawswap
cd clawswap && mix deps.get && mix compile

Clone it anywhere. The command is bin/clawswap in the clone. You run it from inside your project's repo, since that's the repo it acts on; it finds its own folder by itself:

cd <path-to-your-project>
<path-to-clawswap>/bin/clawswap status

Its own Elixir

clawswap doesn't have to run on your project's Elixir. Its .tool-versions pins the Erlang and Elixir it's tested on, and bin/clawswap runs it on those whatever your project pins, so a project on Elixir 1.17 works fine. Everything clawswap runs in your repo (the update steps, the servers) still gets your own PATH, and so your project's Elixir.

  • mise: bin/clawswap runs clawswap through mise exec in its own folder. Install the pinned versions once with cd <path-to-clawswap> && mise install.
  • asdf: the shims read clawswap's .tool-versions by themselves. Install the versions once with cd <path-to-clawswap> && asdf install.
  • Anything else: set CLAWSWAP_ELIXIR_PATH to the bin folders of an Elixir 1.19 and its Erlang, separated by :. clawswap puts them first on its own PATH only. It's also how you pick a version other than the pinned one.

Without any of these, clawswap uses the elixir on your PATH, which has to be 1.19 or newer. When mise or asdf hasn't installed the pinned versions, bin/clawswap says how to.

Put clawswap on your PATH

To type just clawswap, link it into a folder on your PATH. Run this from the clone's root, so $PWD gives the link the full path:

mkdir -p ~/.local/bin && ln -sf "$PWD/bin/clawswap" ~/.local/bin/clawswap

If clawswap is then "command not found", ~/.local/bin isn't on your PATH (check with echo $PATH). Add this to ~/.bashrc or ~/.zshrc and open a new terminal:

export PATH="$HOME/.local/bin:$PATH"

These docs write clawswap; without the link, use <path-to-clawswap>/bin/clawswap instead.

Set up your project

  1. A config. In your project, clawswap init writes a starter clawswap.exs at the repo root, filled in from what it finds there: mix phx.server on port 4000 for a Phoenix app (with mix ecto.migrate when there are migrations), npm run dev (or pnpm, yarn) for a package.json with a dev script (port 5173 for Vite, 3000 for Next), and no servers when it can't tell. Check the servers and steps (see Configuration) and commit it. Prefer YAML? Write a clawswap.yml instead.
  2. The webhook, so new branches show up straight away, sets itself up. Your laptop has no public URL, so GitHub posts to a smee.io channel, which the daemon reads as a stream. The daemon keeps one channel for every project (made the first time it starts, and kept in ~/.local/state/clawswap/smee.json), and the first time a repo comes in it adds the repo's webhook for that channel. Each event goes to the projects of the repo it's about. It uses the same token as the PR titles (GITHUB_TOKEN, else gh auth token), which needs admin on the repo: gh auth login's default token has it if you do, and a fine-grained token needs Webhooks: read and write. If GitHub says no, the project's log and page say why, and 
    clawswap smee
    tries again and prints what to put in Settings > Webhooks > Add webhook instead: the channel as Payload URL, content type application/json, and the events Branch or tag creation, Branch or tag deletion, Pull requests and Pushes. A checkout set up with a channel of its own before there was a shared one keeps it; clawswap smee moves it onto the shared channel (and offers to remove the old channel's webhook). To give a checkout a channel of its own instead, pass one (clawswap smee <url>, or clawswap smee --new for a new one): it's saved in .git/clawswap.json. With no GitHub token at all it can't look for the webhook, so it goes by what arrives: the page says "webhook listening" until a delivery from the repo comes in (a push, or Redeliver on the webhook's ping), then "webhook on", and it keeps when the last one came in, so after a restart it starts on. Without a webhook the watcher still looks every 15 minutes, and whenever you press a key.
  3. PR titles (optional). If the gh CLI is logged in, or GITHUB_TOKEN is set, the list shows the base branch and then the branches with an open pull request, labelled by PR title. Without a token it shows every branch.
  4. Stream Deck keys (optional): through OpenDeck or straight from the page in Chrome; see Stream Deck.
