Configuration

A clawswap.exs (Elixir) or clawswap.yml (YAML) in your repo: the servers a switch restarts, the steps it runs, and a few settings.

The config file

clawswap.exs is evaluated as Elixir and returns a keyword list. You can write the same config as YAML in clawswap.yml (or clawswap.yaml) instead; see YAML.

  • Which file. clawswap uses the closest config, looking from the folder you run it in up to the repo root, so a project in a subfolder can have its own (examples/react-embed does).
  • One per folder. A folder with more than one of clawswap.exs, clawswap.yml and clawswap.yaml is an error rather than a silent pick: keep one.
  • Only servers matters to get going; everything else has a default.
  • Commands. A command or run is a string, run with sh -c, or a list of the program and its arguments.
  • Folders. A cwd is relative to the repo root.
  • Committed. Commit the config. If a switch changes it, the watcher restarts itself to load the new one.

An example

[
  servers: [
    api: [command: "iex -S mix phx.server", cwd: "api", port: 4000],
    web: [command: "npm run dev", cwd: "web", port: 5173]
  ],
  panes: [db: [command: "docker compose up postgres"]],
  prepare: [[label: "Starting Postgres", run: "docker compose up -d postgres", wait_for_port: 5432]],
  steps: [
    [label: "mix deps.get", when: ["api/mix.exs", "api/mix.lock"], run: "mix deps.get", cwd: "api"],
    [label: "Migrating", when: "api/priv/repo/migrations/", run: "mix ecto.migrate", cwd: "api"],
    [label: "npm install", when: ["web/package.json", "web/package-lock.json"], run: "npm install", cwd: "web"]
  ]
]

A fuller one: examples/bmx.exs (Phoenix, Vite, SurrealDB and a beat tracker in docker), and the same as YAML in examples/bmx.yml.

FieldWhat it is
commandRequired. What the pane runs.

steps and prepare

FieldWhat it is
runRequired. The command.
labelWhat the page and keys show while it runs. Default: the command.
nameA short name. Default: the command's first word.
whenWhich changed files make it run (see below). A step without when runs only on a first run or update --all.
cwdWhere, relative to the repo root.
wait_for_portAfter it runs, wait up to 30 s for this port to open (a database container, say).

Steps run in the order written, so put the ones others depend on first.

when

when (and a note's when, and restart_when) matches the paths that changed, relative to the repo root. It is one of these, or a list of them:

FormMatches
"mix.lock"That file, exactly.
"priv/repo/migrations/"Anything under that folder (ends in /).
~r/^docker-compose\.ya?ml$/Paths the Regex matches.
&String.ends_with?(&1, ".lock")Paths the function returns true for.

YAML

clawswap.yml has the same keys, with mappings for keyword lists. Order is kept, so servers and steps run as written.

servers:
  api: {command: iex -S mix phx.server, cwd: api, port: 4000, match: '/phx\.server/'}
  web: {command: npm run dev, cwd: web, port: 5173}
panes:
  db: {command: docker compose up postgres}
steps:
  - {label: mix deps.get, when: [api/mix.exs, api/mix.lock], run: mix deps.get, cwd: api}
  - {label: Migrating, when: api/priv/repo/migrations/, run: mix ecto.migrate, cwd: api}

Regexes

Where .exs takes a Regex (when, restart_when, a server's match), write the string between slashes, quoted so YAML leaves the backslashes alone: '/^docker-compose\.ya?ml$/'. Any other string is a path, as in .exs.

Functions as Elixir strings

Where .exs takes a function, write it as Elixir in a string:

  • short_name is always Elixir.
  • A when or restart_when string starting with fn or & is Elixir.
short_name: 'fn branch -> String.replace_prefix(branch, "feature/", "") end'
steps:
  - {label: mix deps.get, when: ['&String.ends_with?(&1, ".lock")', mix.exs], run: mix deps.get}

Each must be a function of one argument. It's evaluated when the config loads.

A YAML config runs code just as a clawswap.exs does. Treat either as you would any script in the repo: switching to a branch runs that branch's config and steps.

Editing the config from the page

The watcher has a config editor at http://127.0.0.1:8790/settings. The ⚙ at the top of the branch page opens it in a new window, so it works from an app's iframe too. It edits the config clawswap is running, in that config's own format: the settings above as fields, and a row for each server, pane, step and note, which you can add, remove and move up.

  • Save checks first. It makes sure clawswap can load the result before writing it, then restarts the watcher on it.
  • Commit the change. The file is part of your repo, and a switch refuses uncommitted changes.
  • clawswap.exs is changed in place. Only the settings you changed are rewritten. Comments, the Elixir in it and keys the page doesn't show stay as they were. The file is printed by Elixir's formatter, at the repo's .formatter.exs line length or the file's own widest line.
  • clawswap.yml is written afresh, so comments in it are lost. Regexes and Elixir go back as strings.
  • Code fields. A field holding something a plain field can't (a function, a variable, a Regex with options, a command as a list) is shown in monospace as Elixir, or as the YAML's string of Elixir, and saved as written.
  • Regexes in when. In when fields, a line written /like this/ is a Regex.

Saving writes a config, and a config runs as code, so the whole watcher (pages as well as the API) answers only requests addressed to localhost or 127.0.0.1. A site that points its own name at 127.0.0.1 gets 403.
