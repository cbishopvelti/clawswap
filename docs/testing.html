Browser tests

A suite of Wallaby tests in your project that drive Chrome against the servers the session runs, with as many browsers at once as a test needs.

Walkthroughs show one branch's change while you watch. Browser tests are the suite you keep: ExUnit files in the project's browser_tests/ folder, written with Wallaby, that clawswap test runs against the app as clawswap up runs it. clawswap brings Wallaby, chromedriver and the Chrome setup, so the project's own build needs nothing added: a Phoenix app and a Vite one get the same suite.

# browser_tests/chat_test.exs
defmodule ChatTest do
  use Clawswap.Feature, async: true

  feature "the home page opens", %{session: session} do
    session
    |> visit(url(:web))
    |> assert_has(css("h1", text: "Welcome"))
  end

  # Two people at once: each session is a Chrome of its own, with its own cookies and login.
  @sessions 2
  feature "a message reaches the other person", %{sessions: [alice, bob]} do
    alice |> visit(url("/chat")) |> fill_in(text_field("Message"), with: "hi bob") |> click(button("Send"))
    bob |> visit(url("/chat")) |> assert_has(css(".message", text: "hi bob"))
  end
end

Running them

In your project's repo, with the session up:

clawswap test                              # every *_test.exs in browser_tests/
clawswap test browser_tests/chat_test.exs  # files or folders, from where you are
clawswap test --only wip                   # by tag (@tag :wip), or --exclude slow
clawswap test --watch                      # with windows, to watch them

It prints ExUnit's report and exits 1 when a test fails. A failure saves a screenshot of each of the test's browsers in the temp folder (clawswap-screenshots) and prints their paths. --seed and --max-cases are ExUnit's. A browser_tests/test_helper.exs, if you add one, runs first: for helpers the tests share.

Chrome runs headless unless you pass --watch or set CLAWSWAP_HEADLESS=0. Each session gets a window of its own and a fresh profile; tests never use the dev Chrome. They need what walkthroughs need: Chrome and chromedriver of the same major version (CLAWSWAP_CHROME, CLAWSWAP_CHROMEDRIVER) and the servers running.

Writing them

use Clawswap.Feature makes the module an ExUnit case with use Wallaby.Feature, so everything in Wallaby.Browser is there: visit, click, fill_in, assert_has, refute_has, focus_frame, execute_script, take_screenshot and the rest. Its options go to ExUnit.Case: async: true runs the module alongside others, each with its own browsers.

WhatDoes
feature "name", %{session: s} do … endA test with one browser session.
@sessions 2 then %{sessions: [a, b]}That many sessions, each its own Chrome: two users, an admin and a customer, a buyer and a seller.
@sessions [[window_size: [width: 390, height: 844]], []]Options for each session: a phone-sized one next to a desktop one.
url(:web, "/path")A server's address by its name in the config (url("/path"): the first with a port; url(:clawswap): the branch page). It follows the ports in your config, so the tests don't hard-code them.
css/2, xpath/2, button/2, link/2, text_field/2, fillable_field/2, checkbox/2, radio_button/2, select/2, option/2, file_field/2Wallaby's queries, imported. Query.text("…") for text anywhere on the page.

examples/react-embed/browser_tests/app_test.exs has three, one with two sessions.

Phoenix apps

The tests drive the dev server the session runs, with its dev database, so they're end-to-end checks of the app as you run it: give the users and records a test makes names of their own ("alice-#{System.unique_integer([:positive])}"), so runs don't trip over each other or over what you made by hand. They can't use Ecto's SQL sandbox, which needs the tests and the server in one BEAM. For tests that each start from an empty database, use Wallaby inside the app's own mix test as its docs describe ({:wallaby, only: :test}, Phoenix.Ecto.SQL.Sandbox in the endpoint, config :wallaby, otp_app: :your_app). The tests themselves read the same: feature, @sessions and the queries are Wallaby's either way.

Asking Claude for them

In your repo's CLAUDE.md:

Browser tests are Wallaby features in browser_tests/ (https://cbishopvelti.github.io/clawswap/testing.html),
run with `clawswap test` against the running servers. Add or update one with each change to what the app
does, using @sessions when more than one user is involved, and check they pass before pushing.

The folder is browser_tests next to the config; set browser_tests: in the config for another.
