Stream Deck keys

Branch and pull keys on a Stream Deck, through the OpenDeck plugin or straight from the watcher's page in Chrome.

OpenDeck: install the plugin

<path-to-clawswap>/opendeck/install.sh

It can be run from anywhere. It copies the plugin into OpenDeck's plugins folder (~/.config/opendeck/plugins, or the Flatpak's under ~/.var/app/me.amankhanna.opendeck). It's a copy, since OpenDeck doesn't reliably follow a symlink there, so run it again after updating clawswap.

  1. Make sure Elixir 1.18 or newer is on the PATH OpenDeck sees. OpenDeck starts the plugin as bin/plugin, which runs plugin.exs with elixir. A version manager that only sets Elixir up in your shell won't do.
  2. Quit OpenDeck fully (tray > Quit) and start it again; it only starts plugins when it launches.
  3. Drag clawswap branch (category clawswap) onto keys, and clawswap pull and clawswap walkthrough onto one each.

The keys need the project's watcher running (clawswap up).

clawswap branch

Each key either shows the next branch or a branch you name (set in the key's settings).

  • Keys on "next branch" share the list in deck order, row by row. The first shows the base branch, the rest the newest open pull requests.
  • A key shows its branch's PR number and title.
  • Tapping it switches to that branch when you let go: the servers stop, the branch is checked out, the steps it needs run and the servers start again.
  • Holding it for half a second opens the Claude Code thread that made the branch instead.

A bar on the key shows its state:

  • Green: the checkout's branch.
  • Blue: the checkout's branch has new commits on GitHub; press it to pull them.
  • Amber: a switch in progress, with its step.
  • Red: a failed switch.

The checkout's key also has a green outline. The top right corner marks the merge status, as the page's list does, in GitHub's colours: ⎇ the base branch, ● an open PR (green, and the key is tinted green), ◌ a draft PR (grey), ✓ merged into the base (purple, tinted purple), ○ neither.

Open the branch's Claude Code thread

Hold a branch key for half a second and the watcher opens, in your browser, the Claude Code thread that made that branch: the project thread its PR's description links to, or else the session named in the Claude-Session: trailer of its newest commit. On a pull key it's the checkout's branch. The key shows a tick, or an alert when the branch has neither (the base branch, say). It's the same on a deck the page drives.

The watcher opens it with xdg-open (open on a Mac), on the machine it runs on.

clawswap pull

Pulls the branch the checkout is on and restarts the servers if anything came in, like clawswap pull.

clawswap walkthrough

Plays the checkout's walkthrough in Chrome, like its ▶ on the page or clawswap walk: the first one the branch added or changed, else the first one. The key shows its name, the step it's on while it plays (amber), and then whether it ran to the end (green) or failed (red).

Several projects

Each key has a Watcher setting, empty for http://127.0.0.1:27390. Point keys at another project's port to drive several projects from one deck; keys on the same watcher share its list.

The Elgato app

The plugin speaks the Stream Deck SDK 2 protocol and its manifest also lists macOS, so it may run in Elgato's Stream Deck app too. OpenDeck on Linux is what it's built for; the Elgato app hasn't been tried.

From the page, without OpenDeck (WebHID)

The watcher's page can drive the deck itself.

  1. Quit OpenDeck first (tray > Quit), since both would draw on the same keys.
  2. Open the watcher's page (http://localhost:27390) in Chrome or Edge. WebHID is Chromium only.
  3. Press Connect Stream Deck and pick the deck.

The keys show the base branch and then the newest PRs, in deck order, row by row, with the walkthrough and Pull on the last two keys. They look like the OpenDeck keys, with the same coloured bars and marks; tapping one switches, and holding one opens its Claude Code thread. Chrome remembers the deck, so the page opens it again when it loads and when the deck is plugged back in.

  • Keep the tab open. It works while that tab is open; close it and the keys stop.
  • Decks. It knows the Stream Deck (v2), MK.2 and XL. The Mini, Neo and + aren't supported yet.
  • Linux permissions. Your user needs access to the deck's hidraw device. The udev rule OpenDeck installs should cover that; otherwise add one for vendor 0fd9.
  • Not in the embed. An iframe needs allow="hid" for WebHID, so press Connect on the page itself; the narrow embed menu leaves the button out.

This is new and hasn't been tried on a real deck yet. If it misbehaves, OpenDeck still works.

It's Elixir too: app/components/stream_deck.ex calls navigator.hid and a canvas through Hologram's JavaScript interop.
