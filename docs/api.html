API

The daemon's JSON API, for your own control, script or key.

The daemon listens on 127.0.0.1:<port> (27390 by default). Each project's API is under /p/<id>, its id being its session's name (Several projects): GET /p/shop/state. The same paths without /p/<id> answer for the selected project, so a script or key that names no project follows it. The CLI, the Stream Deck keys and the React example all use this API.

Endpoints

RequestBodyAnswer
GET /p/<id>/state200 and the state.
GET /p/<id>/eventsThe state as Server-Sent Events: one data: event with it at once, then another each time it changes, so a page can listen with EventSource rather than poll /state. A comment line every 15 s keeps it open. It ends when the project goes from the daemon. Only under /p/<id>.
POST /p/<id>/switch{"branch": "..."}202 and the state once the switch has started; follow /state's switch. It looks at origin first, so a branch pushed a moment ago is found. Otherwise {"error": "..."}: 409 for uncommitted changes or a switch already running, 404 for a branch that isn't listed.
POST /p/<id>/pull{}The checkout's branch: 202 with switch.pull true, or 202 with "Already up to date" in switch.notes. 409 when not on a branch, 404 when the branch isn't on GitHub.
POST /p/<id>/claude{"branch": "..."}Opens the Claude Code thread that made the branch (the checkout's branch without one) in the browser, on the watcher's machine: the project thread its PR's description links to, else the Claude-Session: in its commits. 200 and {"url": "..."}, or 404 when it has neither.
POST /p/<id>/refresh{}Looks at git and GitHub now; 200 and the state when done.
POST /p/<id>/walk{"name": "…"}Runs a walkthrough in a browser on this machine; 202, then follow the state's walk. 409 while one or a switch is running.
GET /p/<id>/debug/screenshot.pngThe debug panel's last screenshot of its Chrome; 404 before the first.
POST /p/<id>/smee{"url": "…"}Follows this smee.io channel from now on, in place of the one it followed; clawswap smee sends it after saving a new channel.
GET /p/<id>/logThe project's log so far, then each new line as it comes, as plain text. The session's clawswap pane follows it; the project stays in the daemon while something does.

The daemon's projects

RequestBodyAnswer
GET /projects200 and {"projects": [{"id", "name", "root", "port"}], "selected": "<id>"}, in the order they started.
POST /select{"project": "<id>"} or {"next": true}Selects a project, or the one after the selected one; 200 and {"selected": "<id>"}, 404 for no such project.
GET /daemon200 and {"clawswap": "daemon", "port", "pid"}: how clawswap up knows the daemon is running.
POST /daemon/projects{"cwd": "…", "env": {…}}Runs the project whose config is found from cwd, with that shell's environment for its commands; 200 and {"id", "name", "root", "url"}, 422 when the config doesn't load or another checkout has its id. clawswap up and clawswap watch send it. No browser may: it runs the config's code.

POSTs need Content-Type: application/json.

curl -s http://127.0.0.1:27390/p/bmx/state
curl -sN http://127.0.0.1:27390/p/bmx/events
curl -s -X POST -H 'Content-Type: application/json' -d '{"branch":"claude/fix-login"}' http://127.0.0.1:27390/p/bmx/switch
curl -s -X POST -H 'Content-Type: application/json' -d '{"next":true}' http://127.0.0.1:27390/select

FieldWhat it is
currentThe checkout's branch and commit.
dirtyTracked files have uncommitted changes (a switch would be refused).
upstreamThe checkout's branch on origin, and how many commits the checkout is behind it; null when the branch isn't on origin.
branchesThe list, base first. merged is there when every commit is in the base; pr when it has an open pull request.
prsWhether the list comes from open PRs (a GitHub token was found).
webhook"off" (no channel set), "connecting" or "connected".
switchThe last switch or pull: phase is "running", "done" or "failed", step the label of the step it's on. A switch or pull asked for shows as "running" at once, on step "Fetching" with queued true, while clawswap looks at origin before starting it. doneAt (milliseconds) is there once a switch or pull has finished and its servers listen again; it changes with each one, so a page can reload on it. It's gone while the next one runs (and after one fails), so reload on a new time, not on it going away.
walkthroughsThe checkout's walkthroughs; new when the branch added or changed it since it left the base.
walkThe last walkthrough run from the page or API: phase is "running", "passed" or "failed", step its caption.

Who can call it

  • It answers this machine only: the Host header must be localhost or 127.0.0.1, which also stops DNS rebinding. The same goes for the pages, including the config editor.
  • Browsers only from allowed origins, for a project's paths: the daemon's own, that project's servers' localhost and 127.0.0.1 ports, and its config's origins. One project's app can't call another project's paths. A page elsewhere can't make the browser send a JSON POST here without a CORS preflight, which only those origins pass.
  • Webhook deliveries are only a hint to look again; the watcher never acts on their contents.
